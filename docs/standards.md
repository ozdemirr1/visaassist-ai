# Standards and Regulations

Version 0.1 · 2026-11-23 · Lists only what the code or the process applies today, and how it shapes
the system. Targets that are not applied yet are listed separately, so that nothing here claims more
than the repository shows.

## 1. Applied in the code

| Standard | Where | How it shapes the system |
| --- | --- | --- |
| NIST SP 800-38D (AES-GCM), 256-bit keys | `backend/app/storage/crypto.py` | Every document has its own key; file names and entered field values are encrypted too; the authentication tag rejects a changed file. |
| RFC 9106 (Argon2) | `backend/app/auth/service.py` | Passwords are stored only as Argon2id hashes. |
| RFC 6265 (HTTP cookies), `HttpOnly`, `Secure`, `SameSite=Lax` | `backend/app/api/auth.py` | The session token is not readable by page scripts and is not sent by cross-site requests. |
| OpenAPI | generated by FastAPI; `backend/tests/test_openapi.py` | The API is described in a machine-readable contract; error responses are part of it and tested. |
| ISO 3166-1 alpha-2 country codes | `data/destinations.yaml`, requirement files | Destinations are `NL` and `NO`; a new country is a new code, not a new data model. |
| ISO 639-1 language codes | `frontend/src/locales/tr.json`, `en.json` | The interface is in Turkish and English; a test fails when the two files differ in their keys. |
| ISO 8601 dates | API and rule engine | Travel, issue and expiry dates are exchanged and compared in one format. |
| EU Commission Implementing Decision C(2021) 5156 | `data/requirements/eu-tr.yaml` | The harmonised list of supporting documents in Türkiye is the baseline layer of every checklist. |

## 2. Applied in the process

| Standard | How |
| --- | --- |
| PEP 8 (via Ruff, rules E, F, I, B, UP) | Lint runs on every pull request; `main` accepts only changes that pass. |
| Conventional Commits | Commit titles start with `feat:`, `fix:`, `docs:` or `chore:` and name the issue. |
| Architecture decision records | Decisions that are expensive to reverse are recorded in `docs/decisions/`. |

## 3. Regulations

| Regulation | How |
| --- | --- |
| KVKK, Law No. 6698 (Türkiye); GDPR as the reference for EU destinations | Consent before the first upload, encryption, retention of 30 days after the trip, deletion on request, synthetic documents only. A review of the data flows is planned before any real document is allowed (ADR 0006, decision 10). |
| FSEK, Law No. 5846; SMK, Law No. 6769 | The code is protected as a work; computer programs as such are not patentable (SMK Art. 82/2). See the licence. |

## 4. Targets, not applied yet

| Standard | Plan |
| --- | --- |
| WCAG 2.2 level AA | Parts are followed (visible focus outlines, 44 px touch targets on form controls), but no audit has been made. An audit is planned for spring. |
| ISO/IEC 21031:2024 (Software Carbon Intensity) | Model calls already log tokens and cost; a per-file SCI estimate is planned for the spring experiments. |
| ICAO Doc 9303 (machine-readable zone of passports) | Reading the passport's MRZ is planned for spring (ADR 0006, decision 3). |
| Semantic Versioning | The first release will be tagged `v0.1.0` at the end of the fall semester. |
